Дата: 2026-11-12

Коротко: экраны фронтенда сделаны по дизайну (этапы G0–G4 закрыты). Бэкенд протестирован на тестовой базе, но на настоящем Postgres и в Docker ещё не запускался. Ниже — что осталось, по порядку.

## 1. Локальный запуск через Docker Compose (G5.1) — не сделано

- Docker Desktop установлен, но движок не отвечает: команда `docker info` зависает. Пока он не запущен, ничего не собрать.
- Что проверено: `docker compose config` — файл конфигурации валиден.
- Что не проверено: сборка образов, миграции на настоящем Postgres с pgvector, работа `/pipeline` и `/support` в контейнерах, открытие сайта на localhost:8081.
- Что нужно: запустить Docker Desktop и дождаться статуса «Engine running». Потом выполнить `docker compose --profile stub up -d --build`.

## 2. Фронтенд подключён к API (G5.2) — не сделано

- Сейчас все экраны показывают демо-данные из `shared/data`. Запросов к пайплайну нет.
- Нужно написать адаптеры для экранов: бриф, ожидание, пробелы, итог, паспорт, файлы, тарифы.
- Нужна проверка в браузере на локальном стеке: бриф → пробел → ответ → итог.

## 3. Сервер и nginx (G5.3) — не сделано

- Нет домена, сервера и доступа по SSH. Пока этого нет, за этот этап не берусь.
- Что понадобится: `docker-compose.prod.yml`, HTTPS через certbot, лимиты размера запросов, резервные копии Postgres, секреты только в `.env` на сервере.

## 4. Решения, которые нужны от владельца

- **Ключи и адреса API DeepSeek и Kimi**, а также ID моделей. Без них работает только заглушка `stub-llm`, и реальных ответов модели не будет.
- **Провайдер эмбеддингов.** Эмбеддингов у DeepSeek и Kimi не подтверждено. В базе размерность 4096 (миграция 0005, qwen3-embedding); если провайдер даст другую размерность, нужна миграция. Без этого нельзя проверить антифрод на реальных данных.
- **Распределение моделей по задачам.** Сейчас одна модель на все задачи. DeepSeek Flash и Kimi k3 по задачам пока не разведены.
- **Вход пользователей:** Supabase Auth или свой. Сейчас экраны открыты без входа.
- **Вопросы Q8–Q16** из `docs/PLAN-v1.1.md` — без ответов.

## 5. Мелочи во фронтенде, которые видно глазами

- В футере ссылка «Поддержка» ведёт на `#` (`frontend/src/shared/layout/SiteLayout.tsx`, строка 76). Должна вести на `/support`.
- Ссылки «Пользовательское соглашение» и «Обработка персональных данных» в футере — заглушки `#`. Тексты документов нам не передавали.
- На экране входа ссылки «условиями сервиса», «обработкой персональных данных» и «Забыли пароль?» — тоже заглушки `#`.
- В базе знаний переименование демо-файлов `.json` → `.docx` — моя трактовка, её надо подтвердить.
- В профиле цвет текста выпадающего меню отличается от дизайна на 1 px. Владелец это принял.

## 6. Безопасность и инфраструктура

- Форма поддержки `/support` публичная. Защиты от спама (лимит запросов или капча) пока нет. Без неё в продакшен выходить нельзя.
- Письма поддержки пока пишутся в файлы в папке outbox, а не отправляются на почту. Для реальной отправки нужен SMTP (переменная `SMTP_HOST`).
- В `docker-compose.yml` парсер (порт 8000) открыт наружу для отладки. На сервере его публиковать нельзя.
