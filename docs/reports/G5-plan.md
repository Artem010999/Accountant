# G5 — план: подключение фронтенда к пайплайну, локально (Docker Compose), затем сервер (nginx)

Дата: 2026-11-12. Статус: план, ожидает решений владельца (см. «Нужно от владельца»).

- Пайплайн (`backend/pipeline-api`) и парсер (`backend/parser-service`) работают в тестах (PGlite, FakeLlm), реальный Postgres с pgvector и реальный LLM не проверялись.

- Нет входа через Supabase Auth: экраны показываются без авторизации.

## Этап G5.1 — локальный стек в Docker Compose
Состав: `postgres` (образ `pgvector/pgvector:pg16`) → миграции (`npm run migrate`, DEV_SEED=1) → `parser` → `pipeline` (порт 8080) → `frontend` (сборка и отдача через nginx, порт 8081).
Опционально профиль `stub-llm`: OpenAI-совместимый заглушечный сервер для проверки без ключей.

Гейт: `docker compose up -d` поднимает всё без ошибок; `GET /health` на pipeline и parser — 200; миграции применились (таблицы и триггеры есть); `POST /pipeline` для тестового пользователя возвращает `WAITING_FOR_INITIAL_BRIEF`; `POST /support` пишет письмо в outbox; фронтенд по `http://localhost:8081` открывает экраны.

## Этап G5.2 — фронтенд подключается к API
- Адаптеры (`shared/api/`): брифинг (Brief) → `/pipeline`; ожидание (Generating) → статус проекта; пробелы (Gaps) → `NEED_USER_INPUT` / `ANSWER_REJECTED` / `STOP_NOV`; итог (Result) → `COMPLETED`; паспорт (Passport) → записи и claims; файлы (Files) → загрузка через `file_url` и sha256; тарифы (Billing) → `billing_plans`.
- Демо-данные остаются только в тестах и заглушках.
- Авторизация на этом этапе: фиксированный тестовый пользователь из seed (`550e8400-…0000`) через переменную окружения. Вход через Supabase Auth — отдельный этап после решения владельца.
- Тесты: контрактные (ответы API → экраны) с моками fetch; e2e-прогон в браузере на локальном стеке (сценарий: бриф → пробел → ответ → итог).

Гейт: T1–T3; e2e-сценарий проходит в браузере на локальном стеке без ошибок в консоли; ответы API отображаются на экранах дословно; для каждого экрана — список состояний, которые реально приходят от API.

## Этап G5.3 — сервер (nginx)
- nginx перед фронтендом и API: `/` — статика фронтенда, `/pipeline` и `/support` — проксирование на pipeline-api (одна origin, CORS не нужен), внутренний parser не публикуется.
- TLS через certbot (домен владельца), заголовки безопасности, лимиты размера тела (1 МБ для /pipeline, 2 МБ для /support), таймауты под длинные вызовы LLM.
- `docker-compose.prod.yml` с сервисами: postgres, parser, pipeline, frontend+nginx; секреты только в `.env` на сервере, не в репозитории.
- Резервные копии Postgres (pg_dump по расписанию), логи в stdout.

Гейт: `docker compose -f docker-compose.prod.yml config` валидна; локально через nginx (HTTP, без TLS) открываются экраны и работает /pipeline и /support через одну origin; на сервере — HTTPS отвечает, `/health` доступен только внутри, секреты не в git.
