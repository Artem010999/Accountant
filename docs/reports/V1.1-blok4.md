## Решения, которые я принял сам (подтвердить)

1. **Выгрузка берёт данные с экрана, но сверяет их с базой.** Владелец просил передавать 10 секций. Чтобы не выпустить документ с непроверенным текстом, сервер сравнивает каждое значение с сохранённым одобренным. Если хотите, чтобы документ строился только из базы, это одна строка.
2. **Смета одобряется кодом, а не Kimi.** Арифметика и лимиты проверяются калькулятором, модель здесь не нужна. Текстовые поля одобряет Kimi.
3. **Секция 1 (основатель) считается одобренной, если заполнено ФИО.** Блок 1 берётся из профиля, его не аудитирует модель.
4. **Необязательный технологический вызов не блокирует одобрение и выгрузку.**
5. **Блокировка на уровне пользователя.** Один пользователь = один проект.
6. **Модель-аудитор и маршрут.** Задача `audit` идёт в Kimi (как в CJM). В `docs/PLAN-v1.1.md` для `novelty` указан Kimi, а в коде он идёт в DeepSeek. Это расхождение оставлено как было, решение за владельцем.

## Вопросы владельцу

- **Ключ DeepSeek и Kimi, ID моделей** (Q1). Без них аудит и консультант работают только на заглушке в тестах.
- **Проверка на реальном Postgres** (нужен Docker).
- **Шаблон DOCX от заказчика.** Теперь не нужен: документ строит скрипт. Если появится макет с другой вёрсткой, его можно сверить с построителем.
- **Секрет для внутренних маршрутов.** `/pipeline`, `/consultant`, `/export` требуют `x-pipeline-secret`. Браузер его не знает, nginx пока не подставляет. Нужна схема: либо nginx добавляет секрет, либо вход пользователя через JWT на шлюзе (G5.2).
- **Экран чата: вход в него.** Маршрут есть, ссылки из кабинета нет (в дизайне её нет). Нужно решить, откуда открывать чат.
