# Quality gates: фронтенд «Буха» по дизайну

Правило: этап считается закрытым только тогда, когда все его гейты зелёные и есть доказательства (вывод команд, пути скриншотов). Следующий этап не начинается, пока предыдущий не закрыт. Гейт не «почти прошёл» — либо пройден, либо нет.

Ссылки: дизайн `design/project/*.dc.html`, карта экранов `docs/user-flows.md` §1, харнесс `docs/harness.md`, правила `.claude/rules/`.

## Общие гейты (для каждого этапа)

| Код | Проверка | Команда / способ | Порог |
|---|---|---|---|
| T1 | Типы | `npm run typecheck` | 0 ошибок |
| T2 | Тесты | `npm test` (корень) | все зелёные, ни одного `skip`/`only` без причины в комментарии |
| T3 | Сборка | `npm run build -w @passport/frontend` | успешно, без ошибок |
| T4 | Консоль | браузер: открыть каждый маршрут этапа, `read_console_messages` | 0 ошибок (warnings — с объяснением) |
| V1 | Визуальное совпадение | для каждого экрана: скриншот эталона и нашего экрана при 1440 px, сравнение | см. «Критерий визуала» ниже |
| V2 | Текст | `get_page_text` на нашем экране против текстов в `*.dc.html` | все строки из дизайна присутствуют дословно |
| S1 | Нет самодеятельности | `git diff --stat`: только файлы своего этапа | ничего вне зоны владения |

## Критерий визуала (V1)

Экран считается совпавшим, если при сравнении скриншотов 1440 px:
- расположение блоков, порядок и выравнивание совпадают;
- размеры шрифтов, толщина, межстрочный интервал совпадают (визуально, без «на глаз-примерно»: сверяются значения из inline-стилей эталона);
- цвета совпадают с токенами (`tokens.css`), никаких «похожих» цветов вне токенов;
- радиусы, тени, границы, отступы совпадают с эталоном;
- иконки и логотип совпадают по форме;
- отличия только в тех местах, где дизайн сам зависит от данных (длина текста, аватарки, даты) — и это явно записано в отчёте экрана.

Допустимо: субпиксельные различия, антиалиасинг, разный рендер шрифта в разных браузерах.
Недопустимо: любое видимое смещение блока, другой цвет, пропущенный элемент, лишний элемент, текст, не совпадающий с дизайном.

## Этап G0 — фундамент

Закрыт, когда: T1, T2, T3, T4 (`/`, `/admin/users`, `/design-system`), V1 для `/design-system`, S1.
Доказательство: скриншоты `frontend/.visual/G0-design-system-{ref,ours}.png`, отчёт по расхождениям.

## Этап G1 — сайт: Main, Pricing, Auth

Закрыт, когда: T1–T4 по маршрутам `/`, `/pricing`, `/auth`; V1 и V2 для трёх экранов; тесты навигации (CTA ведут на `/auth`, тарифы выбираются, ссылки «Войти» работают); S1.

## Этап G2 — кабинет: Onboarding, Brief, Generating, Gaps, Result, Passport

Закрыт, когда: T1–T4; V1 и V2 для шести экранов и для состояний, которые видны в дизайне (например, ветки «есть файлы» и «анкета» на Brief); тесты переходов по сценарию F3–F9 из `user-flows.md`; S1.

## Этап G3 — Billing, Files, Profile, States

Закрыт, когда: T1–T4; V1 и V2 для всех экранов; тесты состояний (402 пейвол на Free, лимит файлов, истёкший тариф, блокировки); S1.

## Этап G4 — админка: AdminUsers, AdminBilling, AdminGuard, AdminKB

Закрыт, когда: T1–T4; V1 и V2 для четырёх экранов; тесты фильтров и поиска на таблице пользователей; тест, что пункты меню админки ведут на нужные маршруты; S1.

## Этап G5 — подключение к pipeline-api

Закрыт, когда: T1–T3; e2e-тест: поднятый локально pipeline-api (с FakeLlm и PGlite) отвечает на сценарии `WAITING_FOR_INITIAL_BRIEF` → `NEED_USER_INPUT` → `COMPLETED`, и экраны Brief/Gaps/Result показывают то же, что вернул API; ошибки 402/403/422/429 отображаются экранами States; S1.

## Что делает агент, когда гейт красный

1. Не переходит к следующему этапу.
2. Чинит причину, а не симптом (не отключает тест, не ослабляет порог, не добавляет `skip`).
3. Повторяет гейт полностью, не только упавший пункт.
4. После двух неудачных попыток по одному гейту — останавливается и пишет отчёт: что красное, что пробовали, что нужно решить человеку.
