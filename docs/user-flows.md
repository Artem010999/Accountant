# Буха — пользовательские пути и карта экранов (MVP «Паспорт проекта»)

Основание: ТЗ MVP v1.8 (приоритет 1 — DBML v1.8, приоритет 2 — граф n8n «ФСИ 1»).
Рамки: только паспорт проекта + лендинг, тарифы, оплата, админка. Десктоп. Роли: `user`, `admin`.
Заявки, договор, бухгалтерия, отчётность, ООО — вне рамок.

## 2. Гость

### F1. Знакомство → регистрация
1. Лендинг: оффер, как работает, 4 типа сведений, 10 блоков, тарифы, FAQ.
2. CTA «Собрать паспорт бесплатно» → Регистрация. «Тарифы» → страница тарифов → «Выбрать» → регистрация с запомненным тарифом (после онбординга сразу оплата).
3. Ветки: уже есть аккаунт → «Войти».

### F2. Регистрация и вход
1. E-mail + пароль (Supabase Auth). Подтверждение почты письмом.
2. Триггер `handle_new_user` создаёт профиль с `role = user`.
3. Вход: если есть проект → Паспорт (или текущий шаг пайплайна); нет проекта → Онбординг.
4. Ошибки: неверный пароль; почта не подтверждена (повторить письмо); `is_banned` → экран «Доступ ограничен» (403).
5. Восстановление пароля — стандартный флоу Supabase.

## 3. Пользователь: путь от идеи до паспорта

### F3. Онбординг — профиль основателя (Блок 1)
1. Поля: ФИО, e-mail, телефон / Telegram, статус обучения (студент / аспирант / выпускник / не обучаюсь), вуз, регион.
2. Выбор программы: «Студенческий стартап» (активна), «Старт-1» и Сколково — «скоро».
3. Предупреждение до создания проекта: **один аккаунт = один проект**, ФИО закрепляется за проектом, нельзя загружать материалы другого проекта.
4. Для «Студстартапа» статус ≠ студент/аспирант → мягкое предупреждение (Rule Engine потом выдаст warning), но не блок.
5. → Бриф.

### F4. Стартовый бриф — две ветки (G3)
Первый вопрос экрана: «Есть материалы о проекте?». Зона загрузки видна сразу, рядом крупная кнопка «У меня нет файлов».

| Ветка | Условие | Что видит пользователь | Ответ бэкенда |
|-------|---------|------------------------|---------------|
| Файлы | пользователь загрузил файлы; `features.ai_parsing = true` (Pro, Premium) | список файлов со статусами, счётчик `N из file_uploads_limit`, «Собрать паспорт по файлам». Анкета **не показывается** | → S3A → генерация; недостающее уходит в «Пробелы» (F6) |
| Анкета | «У меня нет файлов» (или тариф Free) | вопросы из БЗ с эталонными примерами + в конце свободное поле «Что ещё важно знать о проекте?» | `WAITING_FOR_INITIAL_BRIEF` → генерация (якорь, S4) |

Ветки и состояния:
- Free: вместо зоны загрузки — пейволл (402 `PLAN_UPGRADE_REQUIRED`) с переходом в «Тариф»; кнопка «У меня нет файлов» остаётся.
- Из анкеты можно вернуться к загрузке («Нашлись файлы? Загрузить»).
- Превышение лимита файлов → 429 `FILE_QUOTA_EXCEEDED`.
- Тот же файл (совпал `sha256`) → «Этот файл уже загружен», не парсится повторно.
- Файл с тем же именем, но другим хешем → сохраняется как новый источник.
- Скан без текста → пометка «распознаём (OCR)», дольше.
- Первые файлы или ответы анкеты становятся якорем проекта — показываем это явно.

### F5. Сборка паспорта (`status = generating`)
Видимые шаги: проверка тарифа → фиксация якоря → распознавание документов → разбор по блокам 2–10 → проверка источников и дат → поиск пробелов.
- Живая сводка: сколько найдено утверждений и каких типов.
- Можно уйти со страницы — прогресс сохраняется, по возвращении экран продолжает с текущего шага.
- Ошибка LLM / парсера → «Не получилось, повторить» (без потери загруженного).
- Готово → если есть пробелы → F6, иначе → F7.

### F6. Дозаполнение пробелов (G4 → S6A → U_LOOP → S6B → G5)
1. Слева список пробелов по блокам с прогрессом «3 из 7».
2. Карточка вопроса: формулировка из БЗ, «Как обычно пишут» (эталонный пример), критерий ФСИ, поле ответа.
3. Отправка → ИИ-валидатор:
   - не принят → причина отказа + подсказка, ответ остаётся в поле для правки;
   - принят → показываем чистовую формулировку с разметкой утверждений, «Записать в паспорт» → следующий пробел.
4. «Вернуться позже» — можно выйти, пробелы останутся в списке.
5. Все пробелы закрыты → F7.

### F7. Проверка новизны (ШАГ 7 → G6 → STOP_NOV)
- Free: шаг пропускается, в итоговом чек-листе пометка «Проверка новизны недоступна на базовом тарифе» + апселл.
- Pro / Premium: ИИ считает аналоги.
  - ≥ 2 аналога и измеримое отличие → F8.
  - < 2 → STOP_NOV: форма «Аналог / параметр / у них / у нас», блок 6 → `needs_review`.
  - После 2 попыток доступна кнопка «Продолжить без этого» — стоп-фактор новизны уходит в итоговый чек-лист.

### F8. Итог: допуск и чек-лист (8.1 Rule Engine + 8.2 Навигатор)
1. Статус: `ELIGIBLE` «Можно готовить заявку» / `NEEDS_CLARIFICATION` «Нужно уточнить» / `NOT_ELIGIBLE` «Есть стоп-факторы».
2. Стоп-факторы (блокируют), предупреждения (не блокируют), каждое со ссылкой «Перейти к блоку».
3. Резюме ИИ-Навигатора и пошаговый чек-лист документов (справка из вуза, свидетельство РИД, протоколы и т. д.). Отмечаемые пункты.
4. Сводка подтверждённости: подтверждено документом / факты без документа / планы / гипотезы / со слов.
5. Проект → `status = review`. Действия: «Открыть паспорт», «Скачать DOCX / PDF», «Согласовать паспорт».

### F9. Работа с паспортом
1. Навигация по блокам 1–10 со статусами. Блок 1 — только чтение из профиля.
2. В тексте поля подсвечены утверждения по типу. Клик → панель: тип, статус проверки, источник (файл, страница, цитата), уверенность ИИ.
3. Действия с утверждением: сменить тип (например, «это план, а не факт»), привязать документ, отклонить.
4. «Режим эксперта»: приглушает всё, кроме рисков (факты без документа, потерянные привязки, отклонённые).
5. Ручная правка поля → после сохранения триггер пересчитывает спаны; не найденные → `orphaned` и поле → «Нужна проверка». Показываем, какие утверждения потеряли привязку.
6. «Согласовать поле» → `approved`. Любая правка согласованного поля снимает согласование (показываем предупреждение до сохранения).

### F10. Догрузка материалов позже (через Guard)
- Новый файл / текст сверяется с якорем:
  - `allowed` → обычная обработка;
  - `allowed_with_warning` → обрабатывается, событие видит только админ;
  - `blocked` → экран «Материалы относятся к другому проекту» (`BLOCKED_PROJECT_SWAP`), файл не сохраняется.

### F11. Экспорт
DOCX и PDF. В документ попадает текущая версия; не согласованные поля помечаются. Экспорт ≠ подача.

### F12. Тариф и оплата
1. Кабинет «Тариф»: текущий план, срок действия, использовано файлов, история платежей.
2. «Перейти на …» → подтверждение (цена, скидка за продление `renewal_discount_percent`) → ЮKassa.
3. Возврат: успех (подписка активна до даты) / ошибка (повторить) / ожидание (платёж обрабатывается).
4. Окончание подписки → план «Базовый»: паспорт, файлы и экспорт остаются; загрузка файлов и проверка новизны недоступны.

### F13. Профиль
Редактирование контактов, вуза, статуса. ФИО после создания проекта заблокировано (замок + пояснение).

## 4. Администратор

### F14. Пользователи
Таблица: пользователь, проект, статус проекта, тариф, дата регистрации, бан. Поиск, фильтры.
Карточка: профиль, проект, подписка, события Стража, журнал действий.
Действия: заблокировать / разблокировать, выдать подписку вручную (`provider = manual`, `subscription_granted`).
Роль только показывается — меняется через SQL / service_role (так в DBML).

### F15. Платежи и тарифы
Платежи: сумма, скидка, статус (`pending / succeeded / failed / refunded`), провайдер, ID ЮKassa. Тарифы: цена, срок, лимит файлов, скидка на продление, флаги функций.

### F16. Страж
Пороги `guard_threshold_block` / `guard_threshold_warn` (синглтон `app_settings`). Журнал событий: проект, действие, близость, модель, превью текста.

### F17. База знаний
Документы по программе: тип, версия, действует с, хеш. Загрузка новой редакции. Анкеты / вопросы / примеры — отдельный тип документа (формат — развилка №1 ТЗ).

---

## 5. Сквозные состояния, которые нужно отрисовать
- Пустое (нет проекта, нет файлов, нет платежей).
- Загрузка / генерация.
- Ошибка сети или ИИ с повтором.
- Блокировки: 402, 403, 429, `BLOCKED_PROJECT_SWAP`.
- Тариф истёк.

## 6. Открытые вопросы, влияющие на интерфейс
1. Развилка №2 ТЗ: где хранить отчёт Навигатора — от этого зависит, можно ли открыть «Итог» повторно без перегенерации.
2. Развилка №3: состояние активного вопроса на фронте или на бэке — влияет на «Вернуться позже».
3. Ключи профиля: `name/status` (Rule Engine) vs `full_name/education_status` (справочник) — нужен один набор.
4. Что происходит с ФИО, если пользователь ошибся при онбординге — нужен ли путь через поддержку.
