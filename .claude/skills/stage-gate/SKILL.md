# Прогон гейтов этапа

Вход: номер этапа (G0…G5).

## Порядок

1. Прочитать `docs/quality-gates.md`, раздел этого этапа, и список экранов этапа из `docs/user-flows.md` §1.
2. Запустить T1 `npm run typecheck`, T2 `npm test`, T3 `npm run build -w @passport/frontend`. Сохранить итоговые строки вывода.
3. T4: для каждого маршрута этапа открыть страницу в браузере, вызвать `read_console_messages` (только ошибки). Зафиксировать результат по каждому маршруту.
4. V1 и V2: для каждого экрана выполнить skill `visual-parity-check`.
5. S1: `git status` и `git diff --stat` — все изменённые файлы должны принадлежать этапу. Лишние — сообщить.
6. Сформировать отчёт этапа в `docs/reports/<этап>.md`:
   - таблица: гейт | результат | доказательство (строка вывода или путь к скриншоту);
   - экраны: статус V1, V2, остаточные расхождения;
   - вердикт: ЗАКРЫТ / НЕ ЗАКРЫТ, и что блокирует.
7. Переход к следующему этапу только при вердикте ЗАКРЫТ.

## Если гейт красный

Чинить причину; повторить гейт полностью. После двух неудачных попыток по одному гейту — остановиться и записать в отчёт, что нужно решить человеку. Не отключать тесты и не менять пороги.
