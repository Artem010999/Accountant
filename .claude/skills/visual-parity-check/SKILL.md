# Сверка экрана с дизайном

Вход: имя экрана (например `Main`) и маршрут (`/`).

## Шаги

1. Убедиться, что поднято: эталон на `http://127.0.0.1:8001` (если нет — `cd design/project && py -m http.server 8001 --bind 127.0.0.1` в фоне) и dev-сервер фронта на `http://localhost:5173` (`preview_start` с именем `frontend`).
2. Открыть эталон `http://127.0.0.1:8001/<Имя>.dc.html`, ширина 1440, снять скриншот `frontend/.visual/<stage>-<screen>-ref.png`.
3. Открыть маршрут на dev-сервере, ширина 1440, снять `frontend/.visual/<stage>-<screen>-ours.png`.
4. Сравнить и составить список расхождений в формате: `элемент | эталон | наше | где править (файл)`. Проверять: сетку и отступы, размеры и веса шрифтов, цвета (по токенам), радиусы, тени, границы, иконки, логотип.
5. Текстовая сверка: `get_page_text` на нашем экране; для каждой строки текста из эталона (grep по `<Имя>.dc.html`) — присутствует ли дословно.
6. Исправить расхождения в CSS/вёрстке экрана, повторить шаги 3–5 до пустого списка.
7. Записать результат: статус (совпадает / есть отличия, перечислить), пути к скриншотам, текстовая сверка (количество строк, пропуски).

## Чего не делать

- Не объявлять совпадение по одному скриншоту без текстовой сверки.
- Не менять эталон и файлы в `design/`.
- Не подгонять значения «на глаз», если в эталоне есть точное значение в inline-стилях — брать его.
