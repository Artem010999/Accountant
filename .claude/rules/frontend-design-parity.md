# Правила: фронтенд 1-в-1 по дизайну

Применяется ко всему, что трогает `frontend/`.

1. **Источник правды — дизайн.** Визуал, тексты и состояния берём из `design/project/*.dc.html` и `docs/user-flows.md`. Ничего не придумываем: ни текстов, ни цветов, ни пунктов меню, ни полей формы. Если в дизайне чего-то нет — не добавляем, а записываем вопрос в отчёт.
2. **Токены, не константы.** Цвета, радиусы, тени, шрифты — только через CSS-переменные из `frontend/src/shared/styles/tokens.css`. Новый цвет в компоненте — ошибка; сначала добавь токен в tokens.css (и отметь это в отчёте).
3. **Значения как в эталоне.** Отступы, размеры шрифта, line-height, веса — ровно из inline-стилей эталона, не «округлённые».
4. **Тексты дословно.** Кавычки, тире, неразрывные пробелы — как в эталоне.
5. **Зона владения.** Работаем в `features/<группа>/`. Общие файлы (`shared/`, `app/`) — только на G0 или с явным пояснением.
6. **Тесты обязательны.** Каждый экран: тест рендера ключевых текстов + тесты его сценариев. Не отключать и не ослаблять тесты, чтобы пройти гейт.
7. **Гейты перед переходом.** Следующий этап не начинать, пока `docs/quality-gates.md` для текущего не закрыт, с доказательствами.
8. **Не коммитить.** Не делать git commit/push без явной просьбы пользователя.
9. **Не трогать backend и design.** `backend/`, `packages/`, `design/` — не редактировать в рамках фронтенд-работ.
10. **Честность в отчётах.** Не писать «готово» без фактического вывода проверок. Расхождения с дизайном перечислять, а не замалчивать.
